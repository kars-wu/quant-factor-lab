# 系统架构

## 1. 分层

```text
┌─────────────────────────────────────────────────────────────┐
│ 研究层  multi_agent/                                        │
│   角色(6) → 受限DSL → Gate0 → tranche回测 → 台账/记忆 → 进化 │
├─────────────────────────────────────────────────────────────┤
│ 策略层  strategies/ + engine/ + risk/ + report/             │
│   因子分析/合成 → 选股时序 → 组合与成本 → 指标与图表         │
├─────────────────────────────────────────────────────────────┤
│ 应用层  simulation/ + scheduler/                            │
│   模拟盘引擎/状态/API/前端；每日增量更新与任务监控            │
├─────────────────────────────────────────────────────────────┤
│ 数据层  data/                                               │
│   SQLite(schema/WAL) + 增量更新 + 复权 + 质量检查 + 抓取      │
└─────────────────────────────────────────────────────────────┘
```

依赖方向严格单向：研究层不 import 应用层，应用层不 import 研究层。
两层共享的是 `data/`、`strategies/`、`engine/` 这些基础设施。

## 2. 两条跑数的链路

**A. 研究链路（`multi_agent`）**

```text
DataView(只读快照) ──┐
                     ├─ DSL 编译 → 因子面板(date×symbol)
HypothesisCard ──────┘        │
                              ├─ Gate0：前缀/截面/零权重/覆盖/资金恒等式
                              ├─ tranche 回测：每日 1/H 资金建仓，H 日重叠
                              ├─ 成本压力情景（18bp → 50bp）
                              └─ 台账：evaluations / decisions / memories / budget
```

**B. 模拟盘链路（`simulation`）**

```text
load_panel() → 复权行情面板 → 策略 signal_fn(panel) → 每日快照信号
            → engine.run_strategy_day：到期卖出 → 次日开盘买入 → 记录净值
            → state（SQLite sim_state.db）→ FastAPI → 网页工作台
```

研究链路和模拟盘链路**共用执行口径的语义**，但实现是分开的：
研究用向量化 tranche，模拟盘用逐日状态机。两者对同一策略的信号、
成交价、成本口径应能对上；对不上就是 bug，不要用"口径不同"解释过去。

## 3. 关键口径

| 项目 | 约定 | 代码 |
|---|---|---|
| 信号时点 | T 日收盘后 | `ExecutionSpec.signal_time` |
| 成交时点 | T+1 开盘 | `ExecutionSpec.order_time` |
| 退出时点 | T+1+hold 开盘 | `ExecutionSpec.exit_time` |
| 资金 | 每日 1/hold 资金建一笔，tranche 内等权 | `evaluation/portfolio.py` |
| 现金 | 未投入权重按现金计，收益 0 | 同上 |
| 空仓日 | 保留在日序列里（否则夏普虚高） | 同上 + `gates.check_cash_identity` |
| 成本 | 换手 × 费率；换手 = 新开仓名义权重 | 同上 |
| 基准 | 同池、同 open-to-open 口径的等权 | `datasets/*.py` |
| 股票池 | 过去 N 日均成交额 top-N，shift(1) | `datasets/sqlite_view.py` |
| 选股上限 | `selection_top` 不超过当日可选数 20% | `_rank_picks` |

## 4. 目录职责

| 目录 | 职责 | 不应包含 |
|---|---|---|
| `config/` | 路径、费率、默认参数 | 业务逻辑 |
| `data/` | 存储、抓取、清洗、复权 | 因子定义 |
| `indicators/` | 通用技术指标 | 组合/策略逻辑 |
| `strategies/` | 因子→信号→交易→组合→评估 | 具体"有效因子清单" |
| `engine/` | 回测骨架（订单/持仓/账本） | 研究口径 |
| `simulation/` | 日频模拟盘与工作台 | 研究实验脚本 |
| `multi_agent/` | 研究治理与挖掘流程 | 行情数据读取细节 |

## 5. 工程上已经踩过的坑（都写成了检查）

1. **动态池未来函数**：用全区间平均成交额选股 → 改为滚动 + shift(1)
2. **零权重 NaN 传播**：`0 * NaN` 让稀疏事件因子污染覆盖池 → `gates.blend` 显式跳过 0 权重
3. **同日买卖顺序**：收盘卖出的现金不能用于当日开盘买入 → "开盘买 → 收盘卖"
4. **杠杆放大**：每笔用 1/H 资金但没按入选数量均分 → 实际杠杆 = 入选数
5. **空仓日被 dropna**：夏普虚高 → 日历完整性检查
6. **选股上限 > 池子规模**：变成买整池 → 20% 截断
7. **按初始资金固定仓位**：没有复利 → 按当日可用现金滚动分配
8. **同股票重叠持仓被覆盖**：按 trade tuple 键控，而不是 symbol

## 6. 未完成/刻意留白

- 分钟级执行、集合竞价量、盘口冲击：没有数据，不假装有
- 真实资金会计（未复权价 + 当时股数 + 公司行为）：`engine/` 只做了简化
- 行业中性化：接口在（`cs_regress_residual`），行业映射表需要自己接
- 最终保留段的物理隔离：见 `docs/multi-agent.md` 第 7 节，仓库只提供访问登记，不提供容器隔离
